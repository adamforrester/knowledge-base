## Overlay modeling research: Dialog vs Drawer vs Sheet (as of Oct 2026)

**Bottom line:** Where the field could be checked, it mostly ships a separate Drawer/Panel/Sheet component, not one Dialog with a placement prop. That supports option **B**, or our knowledge base's position. Several of those systems still build the Drawer on the shared dialog or overlay primitives underneath. **Option A has real precedent too:** Primer and React Spectrum use one Dialog with a placement or container switch. **Option C has none:** no system I checked leaves overlay shape to hand edits.

I used about 40 tool calls. Several official doc sites block fetching (M3, Fiori, Atlassian, Base Web, the new Polaris site), so some cells come from package source on jsdelivr or GitHub raw, or from secondary search results. The flags at the end list which.

### Answers to the six questions

1. **How systems model it.** Most ship a separate Drawer, Panel or Sheet: Fluent, Atlassian, Chakra, Ant, Base Web, shadcn, eBay, Carbon (through IBM Products) and M3. Two ship one Dialog with a placement or container prop: Primer and React Spectrum. Where the source shows a shared base, it is the dialog: Fluent `OverlayDrawer` wraps `Dialog`, shadcn Sheet extends Dialog, and M3's sheet dialogs extend `AppCompatDialog`. Atlassian, Ant and Base Web share only lower layering and focus primitives.
2. **Titleless or tabbed headers.** Accessible names without a visible title are well established: Atlassian `label`/`titleId`, React Aria `aria-label`, Radix's VisuallyHidden title, Polaris `accessibilityLabel`. Tabs in the header appear only in Fiori's View Settings Dialog. Nobody ships a "tabs header" variant, so it is reached by composition.
3. **Footers.** Carbon Modal and Fluent Drawer pin the header and footer while the body scrolls. No system I checked offers a pinned-vs-in-flow toggle prop. Where the footer is configurable at all, it is a slot or composed part (Fluent, Chakra, shadcn, Polaris) or Ant's `footer` prop.
4. **Filter panels.** No system ships a "FilterDrawer" component. Filters are a **pattern** placed in a panel or dialog: eBay modal panel, Fiori dialog, Carbon (container unspecified). Polaris moved away from a sheet to per-pill popovers. The "See N results" pinned CTA is documented by eBay and Fiori Android.
5. **Cart drawer starting below the header.** No e-commerce system documents it. The nearest precedent is **Carbon IBM Products SidePanel**, which sits `inset-block-start: 3rem` with height `calc(100% - 3rem)`, so it starts below the 48px UI shell header. Chakra's Positioner padding and Ant's `getContainer` are the mechanisms other systems give you.
6. **Content-height bottom sheets with rounded corners.** These are their own component in M3 (Bottom sheet), Apple (sheet with detents and grabber), shadcn (Drawer with snap points and handle), eBay (Context and Focus sheets) and React Spectrum (Tray, chosen as a dialog type rather than a separate component).

### Synthesis

**Which option the field supports.** Option **B (a second component)** has the majority. It is mostly drawn on the line we already drew: Dialog for centered forms and confirms, Drawer/Panel for edge surfaces. Option **A** is defensible, and Primer and React Spectrum ship it. Its cost shows in our own list, though: tabs header, pinned-or-in-flow footer, edge widths and divider variants are all edge-surface concerns, and they would land on a component that also does confirms. Primer's warning that custom header and footer renderers "may violate Primer UX principles" is the failure mode A invites. Option **C** has no precedent.

**Where our knowledge base sits.** "Separate `Drawer` on a shared Dialog base" is not an outlier. **Fluent 2 is that architecture almost exactly**: `OverlayDrawer` wraps `Dialog`, has its own Header, Body and Footer, and has `modalType`, which is our `modal` prop. shadcn (Sheet extends Dialog) and M3 Android (SheetDialog on AppCompatDialog) match it too. The evidence also supports reserving `Sheet` for the gesture and detent bottom surface: M3, Apple, shadcn's Drawer and eBay all treat the drag, detent and grabber surface as its own thing. Two cautions:

- **The names are not settled.** shadcn calls the edge panel "Sheet" and the gesture surface "Drawer", the reverse of ours. eBay says "Panel", Carbon says "SidePanel". Pick ours knowingly and document the mapping.
- **The slot anatomy is confirmed.** Fluent, Chakra, shadcn and React Aria compose header, body and footer. Ant (`footer`, `extra` props) and Primer (`title`, `renderFooter`) are the config-style holdouts.

**Approaches not on our list:**

1. **Responsive container switching.** React Spectrum (`type` plus `mobileType`), Primer (responsive `position`) and shadcn's Dialog-or-Drawer recipe change the surface per breakpoint. That fits our case directly: a 492/550px end drawer on desktop becomes full-screen or a bottom sheet on mobile. Whatever we pick needs a per-breakpoint placement, not one fixed value.
2. **Treat filters as a pattern, not a component.** Build it from Drawer slots plus a "See N items" CTA, as eBay and Fiori do. Polaris's per-pill popovers are a third alternative for desktop.
3. **Inline or push drawers** (Fluent `InlineDrawer`, Carbon `slideIn`, eBay non-modal Panel) are a separate non-modal mode, which supports keeping `modal` as a prop.
4. **A container or offset prop** for the below-header cart: Carbon's fixed top offset, Chakra's Positioner padding, Ant's `getContainer`.

### Not verified

- **M3:** the side-sheet and bottom-sheet guidance pages would not render. Modeling comes from MDC-Android source and docs, not from m3.material.io, and header/footer guidance is unchecked.
- **SAP Fiori:** the site returned 403. View Settings Dialog details and the Android "Show n Results" button come from search snippets, which mixed Fiori versions.
- **Base Web:** the docs page was empty. Only the source was checked, so header, footer and accessible name are unknown.
- **Chakra:** I inferred it runs on the Ark dialog machine from the matching props; the page does not say so. What `contained` does is undocumented.
- **Polaris:** `s-modal` `accessibilityLabel` comes from a community example; I did not reach the official reference. Whether `Sheet` is formally deprecated is also unconfirmed.
- **Apple HIG and Fluent:** neither covers titleless headers or names a title-free accessible name.
- **Retailers:** no public design-system documentation found for Nike, Zalando, ASOS, H&M, Farfetch or Adidas.
- **Baymard:** the filtering-apply (#1125) and added-to-cart findings are paywalled. Only headlines were seen.
- **Cart below the header:** no e-commerce documentation found. Carbon IBM Products is the only documented precedent, and it is an enterprise shell, not a storefront.
- **Spectrum 2:** I did not check whether it adds a side drawer. The React Spectrum v3 findings stand.
